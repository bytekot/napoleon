## B6. Обработка ненайденной задачи (реестр багов legacy)

**Файлы:** `packages/vue-app/src/components/task/TaskItem.vue`, `packages/vue-app/src/stores/tasks.ts`

В индексе-реестре фикс B6 изначально был назначен на Этап 3; решением пользователя формально отложен в бэклог.

Сам баг legacy (`useTask` типизирует возможный `undefined` как `Task` — ложь типов, при промахе crash на деструктуризации) в Vue-реализации не воспроизведён: getter `taskById` возвращает `Task | undefined` (сделано на Этапе 1), TaskItem защищён `v-if="task"` и guard'ом `if (!task.value) return` в `isOverdue`.

**Временное поведение (текущий код, оставлен без изменений):** при отсутствии задачи TaskItem рендерит пустой `div[data-task]`. В контексте TasksList пустая обёртка получает стиль `.container div { margin-bottom: 10px }` — невидимый зазор 10px.

**Возможные сценарии возникновения:** рассинхронизация `ids` и `entities`. Сейчас store поддерживает синхронность во всех actions (create/edit/delete, включая откаты при ошибке), поэтому guard — защитная мера.

**Варианты решения:**
- Store: dev-инвариант / чистка — удаление из `ids` записей без соответствующей entity при обнаружении рассинхрона
- Компонент: не рендерить пустую обёртку `data-task` (перенести `v-if` на корень) либо явная визуализация ошибки
- Тесты: покрыть сценарий «id есть в списке, entity отсутствует»

**Статус:** Отложено решением пользователя. Не блокирует Этап 3.

## UTC-1. Overdue: date-only `dueDate` парсится как UTC-полночь

**Файл:** `packages/vue-app/src/components/task/TaskItem.vue` (computed `isOverdue`)

`new Date('YYYY-MM-DD')` возвращает UTC-полночь, тогда как `now` — локальная полночь (`setHours(0, 0, 0, 0)`). В часовых поясах с отрицательным смещением от UTC задача «на сегодня» ложно получает класс `overdue` (UTC-полночь уже наступила относительно локального начала дня). В UTC+ поясах (зона проекта) не проявляется.

Наследуется из legacy 1:1 (`components/task/component.tsx` — та же конструкция `new Date(dueDate) < now`), не регрессия миграции. Пересекается с B9: из-за формирования `dueDate` без zero-padding (`"2026-11-1"`) парсинг становится локальным — поведение overdue различается в зависимости от формата строки.

**Варианты решения:**
- Сравнение в локальных датах: конструировать Date из частей (`new Date(y, m - 1, d)`)
- Или лексикографическое сравнение строк `YYYY-MM-DD` (корректно при zero-padding)
- Решать вместе с B9 при переносе календаря (Этап 5) — единый формат `dueDate`

**Статус:** Отложено. Не блокирует Этап 3.
