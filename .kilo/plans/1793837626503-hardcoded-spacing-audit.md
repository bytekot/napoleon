# Ревизия хардкодных значений в компонентах

## Цель
Проанализировать хардкодные значения в компонентах и определить, какие из них следует повысить до токенов spacing-шкалы (`$space-xs/s/m/l/xl/2xl/3xl`).

## Контекст
После введения модульной шкалы spacing в `_primitives.scss` необходимо проверить компоненты на наличие числовых значений, которые можно выразить через токены шкалы.

### Шкала spacing (доступные токены):
```scss
$space-xs: 4px;
$space-s: 8px;
$space-m: 12px;
$space-l: 16px;
$space-xl: 24px;
$space-2xl: 32px;
$space-3xl: 64px;
```

## Результаты анализа

### Компоненты с хардкодными значениями

#### 1. CalendarYear.vue:50
```scss
margin-bottom: 10px;
```
**Рекомендация:** Заменить на `$space-s` (8px, разница -2px) или `$space-m` (12px, разница +2px).
**Предпочтительнее:** `$space-s` — меньшее отклонение, соответствует компактному отступу между элементами.

#### 2. TaskForm.vue:65
```scss
margin: 0px 0px 0px 10px;
```
**Рекомендация:** Заменить `10px` на `$space-s` (8px) или `$space-m` (12px).
**Предпочтительнее:** `$space-s` — стандартный отступ для UI-элементов.

#### 3. TaskForm.vue:67
```scss
padding: 0 5px;
```
**Рекомендация:** Заменить `5px` на `$space-xs` (4px, разница -1px).
**Обоснование:** Минимальный padding для кнопки, `$space-xs` подходит.

#### 4. TaskItem.vue:139-142 (галочка чекбокса)
```scss
left: 8px;
top: 4px;
width: 5px;
height: 10px;
```
**Анализ:** Это координаты и размеры псевдоэлемента-галочки внутри чекбокса 20x20px.
- `left: 8px` → `$space-s` (8px) — точное совпадение
- `top: 4px` → `$space-xs` (4px) — точное совпадение
- `width: 5px` и `height: 10px` — **оставить как есть**. Это геометрические размеры декоративного элемента, привязанные к размеру чекбокса. Не являются spacing-значениями.

**Рекомендация:** Заменить только `left` и `top`, размеры оставить хардкодными.

### Значения в theme.scss (не требуют изменений)

Следующие хардкодные значения в theme.scss являются **семантическими токенами** и не требуют замены на примитивы:

| Токен | Значение | Причина оставить |
|-------|----------|------------------|
| `--font-size-button` | 13px | Font-size, не часть spacing-шкалы |
| `--font-size-action-area` | 32px | Font-size |
| `--line-height-*` | 16px, 35px | Line-height, отдельная категория |
| `--space-card-mini` | 3px 15px 5px | Составное значение, не мапится на одно значение шкалы |
| `--space-form-toggle-minimized` | 8px | Уже семантический токен |
| `--space-action-area` | 4px 20px | Составное значение |
| `--space-year-grid-gap` | 10px 60px | Составное значение |
| `--space-year` | 10px 15px | Составное значение |
| `--size-*` | различные | Размеры элементов — отдельная категория от spacing |

**Примечание:** Некоторые одиночные значения в theme.scss можно было бы выразить через примитивы (например, `--space-form-toggle-minimized: 8px` → `#{$space-s}`), но они уже являются семантическими абстракциями. Решение об использовании примитивов vs хардкода в определениях семантических токенов — вопрос архитектуры темы, а не компонентов.

### 3. Обновить TaskItem.vue
- Строка 139: `left: 8px` → `left: $space-s`
- Строка 140: `top: 4px` → `top: $space-xs`
- Строки 141-142 (`width: 5px`, `height: 10px`) — **не изменять**
- Добавить `@use '../../styles/primitives' as *;` в `<style>` блок

### 4. Проверки
- `pnpm check` — убедиться, что нет ошибок компиляции
- Визуальная проверка компонентов (особенно чекбокса в TaskItem)

## Вне скоупа
- Изменение значений в theme.scss (это архитектурное решение о структуре тем)
- Приведение составных значений к единой системе (отдельная задача)
- Изменение font-size и size токенов
- Border-width значения (1px) — это не spacing

## Риски
- Визуальные изменения минимальны: наибольшие отклонения ±2px
- Чекбокс галочка: замена left/top на токены не должна повлиять визуально (точные совпадения)
