# Архитектура темы Napoleon

## Структура файлов

```
src/styles/
├── _primitives.scss   # Абстрактные токены (SCSS-переменные, compile-time)
├── theme.scss         # Семантические токены (CSS custom properties, runtime)
└── index.scss         # Точка входа стилей
```

## Уровни абстракции

### 1. Примитивы (`_primitives.scss`)

Абстрактные дизайн-константы. Существуют только на этапе компиляции SCSS. **Не попадают в CSS-рантайм.**

Категории: `$color-neutral-*`, `$font-size-*`, `$space-xs/s/m/l/xl/2xl/3xl`, `$radius-s/m/full`, `$duration-*`, `$ease-*`

Правила:
- Типизированы по категории (нельзя использовать `$space-10` в `--size-*` токене)
- Не доступны в компонентах напрямую
- Изменяются только при пересмотре дизайн-шкалы

### 2. Семантические токены (`theme.scss :root`)

CSS custom properties, доступные в рантайме. Ссылаются на примитивы через SCSS-интерполяцию `#{$var}`.

Категории: `--color-bg-*`, `--color-text-*`, `--space-*`, `--radius-*`, `--size-*`, `--shadow-*`, `--transition-*`, `--font-*`

Правила:
- Каждый токен выражает дизайн-намерение, а не CSS-свойство
- Использует примитивы через `#{}` когда значение совпадает с существующим примитивом того же типа
- Может содержать хардкод, если соответствующего примитива нет (например, `--font-size-button: 13px`)
- Compound-значения используют `#{}` для каждой части, где есть соответствующий примитив

### 3. Компоненты (`.vue <style>`)

Используют **только** семантические токены через `var()`.

Допустимый хардкод:
- Локальные layout-решения, уникальные для компонента
- Значения, которые не являются частью дизайн-системы и не будут переиспользоваться
- Детали реализации (например, координаты pseudo-element)

Запрещено:
- Прямое использование примитивов (`$space-10`, `var(--color-neutral-200)`)
- Создание узкоспецифичных семантических токенов для единственного использования

## Принцип повышения токена (Token Promotion)

Значение живёт как хардкод в компоненте до тех пор, пока:
1. Не начнёт повторяться в нескольких компонентах с **одинаковым смыслом**
2. Не станет частью дизайн-решения, которое может измениться глобально

Тогда оно повышается до семантического токена в `theme.scss`.

Обратный процесс (token demotion): токен, использующийся один раз и не выражающий общую идею, понижается до хардкода.

### Открытые вопросы
- Нужны ли примитивы для всех хардкодных значений в семантических токенах? (Например, `--space-form-header: 12.5px 8px` — дробное значение, подгоночное)
- Стоит ли ввести `$space-0: 0` как примитив для compound-значений вроде `0 7px`?
- Component-токены (`--button-*`) — оставить в theme.scss или вынести в отдельный файл?
